# 许可证与专利审查

> **核心结论：代码许可证（MIT）与 H.264 专利许可（第三方专利池）是两件独立的事。
> 本仓库只回答前者，不回答后者。**

## 1. 本仓库的代码许可证

| 项目 | 结论 |
|---|---|
| 许可证 | MIT（见 `LICENSE`） |
| 允许商用 | 是 |
| 允许修改与再分发 | 是（需保留版权与许可声明） |
| 是否授予专利许可 | **否**（MIT 无明示专利授权条款） |
| 是否存在 Copyleft 传染 | 否 |

## 2. H.264 专利（独立问题）

- H.264/AVC 的实现与分发可能涉及第三方专利，通常通过专利池（如 Via LA / 原 MPEG LA
  的 AVC 池）授权。
- 本项目**不提供**任何专利许可，也不对"是否需要许可"作判断。
- 使用场景（自用、内部服务、分发软件、硬件实现、对外 SaaS）导致的义务可能不同，
  需使用者自行评估。
- 详见 `PATENTS.md`。

**禁止在代码注释、README 或文档中写入"本实现免专利"或类似的表述。**
这类表述既不准确，也可能给使用者造成误导。

## 3. 参考项目边界：thesyncim/goh264

goh264 是 LGPL-2.1 项目，且采用"FFmpeg 解码器结构化移植"的路线。

| 借鉴内容 | 允许 | 说明 |
|---|---|---|
| 架构划分（NAL/Syntax/Entropy/DPB 分层） | ✅ | 属于工程结构思想 |
| 验证体系（Oracle 差分、语料 manifest、Translation Ledger） | ✅ | 属于方法论 |
| 公共 API 设计取向（根包简洁、Clone/Validate） | ✅ | 接口思想，非表达 |
| 源码逐行转写 | ❌ | 受 LGPL 约束的表达 |
| 复制其查表数据/注释/结构体布局 | ❌ | 同上 |
| 链接其包或引入其代码 | ❌ | 会引入 LGPL 义务 |

执行规则：

1. 实现依据 **H.264 规范条款 + 公开语法表 + 自有推导**，不以第三方源码为蓝本。
2. 差分手段是**行为对照**（同一码流喂给 FFmpeg/JM，比较解码结果），不是"读源码再翻译"。
3. 任何未来的第三方代码复用，必须先在本文件增补一节：来源、许可证、兼容性结论、
   替代方案，经评审后再动代码。
4. FFmpeg 仅作为开发期 Oracle 工具，通过 `os/exec` 调用命令行，不链接、不复制其源码。

## 4. 依赖审查清单（每次新增依赖都必须过）

- [ ] 是否可以用标准库完成？
- [ ] 许可证是否与本项目 MIT 兼容（MIT/BSD/Apache-2.0 通常可以；GPL/LGPL 需单独评估）？
- [ ] 是否引入 CGO 或外部动态库？（任一为是 → 直接拒绝）
- [ ] 是否会把 FFmpeg/x264 变成运行时依赖？（是 → 直接拒绝）
- [ ] 是否需要在 `docs/supported-features.md` 中登记其影响？

> 当前状态：`go.mod` 无任何第三方 `require`，仅使用标准库。

## 5. 测试语料的许可

- FFmpeg FATE 样本：遵循其各自来源的许可，使用时在 `testdata/manifest.json` 中记录
  `source` 字段。
- x264 生成的样本：属于"用工具生成的内容"，不是 x264 源码，但需在 manifest 中注明生成参数。
- 自制合成样本：与本仓库同许可。
