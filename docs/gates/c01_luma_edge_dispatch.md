# C01：亮度整边包装层不逃逸

A01 的固定目标微基准和直接汇编均可零分配，但 A07 在调用者闭包内新建局部数组时，
Prepared Luma8 实测 1 alloc/op。原因是整边 slice 经函数值转发，丢失具名汇编入口的
`noescape` 信息；逐段回退还需要稳定的跨包调用边界。

本次只改变调用边界：按原诊断槽选择具名 SSE2 或 Generic，非 amd64/purego 直接调用
Generic；逐段 FilterLuma8 保留具名跨包边界。原诊断和强制后端选择保持有效，不修改汇编、
滤波公式、邻域准入、强滤波条件读取或逐段回退语义。旧调用无需额外 padding。

验收回归在闭包内创建数组，测试水平/垂直完整边及少一个字节的回退；底层另用逐行保护页
比较公开整边入口与 Generic，包含最后一行只有 q2、没有 q3 的水平强滤波。
实际解码帧平面原本已在堆上；局部缓冲门禁与端点分配是两项指标。

## 验收结果

相同回归在 `9f493b3` 的四格均为 1 alloc/op；修复后四格均为 0，
编译器对 Prepared Luma8 报告 `data does not escape`。amd64 显式后端、purego 和
Windows/386 定向测试通过；Windows/arm64 仅编译。CGO=0 全仓 gofmt/vet/build/test、
依赖检查及语料清单通过。短 IDR/I/P/B 的 FFmpeg 像素和加权编码 Oracle 通过。

同机以 C00 冻结二进制和 C01 二进制各测五次，奇偶轮交换先后，原 1080p 直接 AU，
IDR 500ms、I/P/B 1x。最终中位耗时分别为 42.95→36.60ms 和 1027.38→935.49ms；
未观察到端点回退，不把下降幅度归因于局部数组消除。首版具名调用保留两次检查，
复测有垂直边变慢；最终改为一次 Try 分派。最终活跃边各格耗时变化约 -10.1% 至 +2.0%。
仍有代价：含固定目标重置的零强度/零阈值控制格增加约 1.5–2.5ns/op，早退行为未改变；
按局部零分配及端点门禁采纳，不宣称所有微基准无回退。

原始耗时与分配（含首版及复测）见 [c01_luma_edge_samples.json](c01_luma_edge_samples.json)。
未重新运行 300 帧整矩阵、race 或非本机原生测试；本次不改并发或滤波算术。
