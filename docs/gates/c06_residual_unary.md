# C06 复评：CABAC 残差幅值前缀（未采纳）

**决定：不默认启用。** 这次的新候选在 High10 唯一补测中五对均更快，配对中位耗时下降 4.94%；但首轮的配对中位只下降 1.46%，IDR 两轮都未确认同向收益。未满足事先确定的主端点及 IDR 联合判据。生产 `Bin` 和残差循环恢复并核对与基线相同。

## 从真实流选热点

冻结 `0fdfbb2`。Ryzen 7 5700X、Windows/amd64、Go 1.27.4、CGO=0、GOAMD64=v1、GOMAXPROCS=16、Threads=1。独立 CPU 采样中，`decodeResidual` 在 High10 的累计/自身占比为 28.04%/3.44%，IDR 为 24.59%/4.05%。High10 采样还包含计时之外的输入处理和像素哈希，这些占比不等于正式端点占比。显著性循环调用的 `Bin` 仍要原样执行，位置选择自身没有明显采样热点；幅值的同上下文内层循环是更好的候选。

独立串行计数，保留按扫描长度统计的实际调用次数。`sig`/`last` 是读取的两类位置 bin 数；幅值前缀在系数绝对值大于 1 时进入，`ones` 为内层循环返回的 1 数，不含结束用的 0 或 escape 的 bypass 位。计数版不参与正式计时。

| High10 | 4 | 367,047 | 1,069,187 | 924,645 | 942,551 | 4,947,194 |

候选只替换 `decodeResidual` 的 2..15 幅值前缀循环：每次前缀验证同一 `Context` 一次，状态在循环内更新，退出时写回。仍逐 bin 归一化，保留粘性错误和最后一次归一化失败时已返回的 1；不预读，不改任意 scan 校验、幅值 escape 或符号位。按原规则选择 4:2:2 DC 的上下文，不变更 B04 的扫描选择。实现仅留作 `residual_unary_candidate_test.go`；它不是之前否决的 MPS 快路。

## 端点验收

High10 使用 1080p 单 slice 300 帧 `Sequence` 1x，每次核对独立 FFmpeg 像素摘要；IDR 用单帧 `DirectAU_Auto` 500ms，两版及两轮分别执行独立 FFmpeg 像素 Oracle。每组五对独立进程，交替先后；构建、profile、计数、Oracle 与正式计时不重叠。所有耗时、FPS、分配、输入及二进制身份见[原始样本](c06_residual_unary_samples.json)。

| 输入 | 轮次 | 两侧耗时中位 | 两侧中位变化 | 配对变化中位 |
|---|---|---:|---:|---:|
| High10 | 首轮 | 11.100 → 10.597 s | −4.53% | −1.46% |
| IDR | 首轮 | 39.894 → 40.149 ms | +0.64% | −0.29% |
| High10 | 唯一补测 | 9.730 → 9.053 s | −6.96% | −4.94% |
| IDR | 唯一补测 | 35.649 → 36.649 ms | +2.80% | +0.34% |

两侧独立取中位会掩盖本机运行波动，不把首轮的 −4.53% 解释成配对达标。补测 High10 值得作为后续研究线索，但不能拿它替代 IDR 门槛，也不能据此仅对 High10 启用。联合门槛失败即停止；没有跑 High/三份留出端点，没有做 C05+C06 组合测试。

## 正确性与复跑

- 幅值前缀逐状态与原 `Bin` 循环对照：归一化区间 256..511、代表性 pStateIdx、两种 MPS、非法 Context、0..24 尾部位、读位位置和后续 Peek；单列 nil、已终止和粘性错误。测量版通过 CABAC 和 decoder 非缓存测试及上述端点像素校验。
- 差分与诊断微基准可在最终树复跑：`go test ./internal/entropy/cabac -run '^TestResidualUnary_' -bench '^BenchmarkResidualUnary_Level_Compare$' -benchtime=200ms -count=5 -benchmem`。核测只解释机制，无权覆盖端点结论。
- 在同一测试二进制中，幅值 2/3/8/15 的五样本中位分别为 15.57→14.66、22.52→18.84、51.08→37.55、80.35→50.65 ns/op，均为 0 B/op、0 allocs/op。长前缀的局部收益较大，不能据此推断任意流的端点吞吐。
- 最终树通过 CGO=0 的 gofmt、vet、build、全库测试、依赖和语料检查，以及相关 purego/386、bitstream/CABAC/DPB/decoder 的 race、CABAC 算术与残差各 5 秒 fuzz 烟测。fuzz 使用最终生产入口；候选由差分和上述测量版回归覆盖。未新增汇编，未重跑六目标交叉编译。
- 要复测候选端点，在单独工作树将测试专用 helper 移为生产文件，并仅把 `decodeResidual` 中 `level = 2` 和随后的重复 `Bin` 循环替换为 `level = d.residualUnary(&ctx[levelBase[cat]+inc])`，两侧用相同测量入口。现有生产树不自动启用候选。
