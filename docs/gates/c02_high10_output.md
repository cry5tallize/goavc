# C02：High10 输出按行打包

amd64 默认构建把原生 uint16 平面逐行复制到独立的小端帧缓冲，交给 Go 的批量 copy；
purego 与其他架构继续显式写小端。源的字节视图只在单次调用内存在，长度恰好是有效采样
的两倍，不读取 stride 填充，不留存或向调用方暴露内部内存。裁剪、PTS、Release/Clone
和 DPB 所有权不变。

Ryzen 7 5700X、Windows/amd64、Go 1.27.4，CGO0/GOAMD64=v1/GOMAXPROCS=16、Threads1。
冻结父版本 `fb248ef` 与候选，各五个独立进程交错测量：

| 工作量 | before | after |
|---|---:|---:|
| 完整 1080p toFrame（含三平面裁剪、分配及 Release） | 3.93 ms | 0.61 ms |
| 原 High10 300 帧单 slice（含输出） | 14.70 s | 11.94 s |

表中为两侧各自中位数。端点五对同向，配对降幅中位 **13.5%**、范围 4.9%–22.2%；
两侧中位数之比为 -18.8%，波动较大，不能把整个差值归给打包。每次端点都在计时外
验证完整 FFmpeg 原生像素；帧级微基准仍为 4 alloc/op，行打包局部数组为 0 alloc/op。
全部耗时、分配和输入身份见 [样本](c02_samples.json)。

最小切片、非对齐地址、奇数宽和完整 uint16 位模式与独立小端编码对照；
三平面左/上裁剪及修改输出不污染内部图像通过。另跑 purego 和 checkptr=2 边界测试；
整行快路调用 Go 自带 copy，无新汇编读取逻辑。未单独运行保护页。
