# M6接手记录：YUV与Annex-B NAL I/O，整体WIP

日期：2026-11-14；分支`feat/m6-streaming`；Go1.27.4 windows/amd64。
首批完成Implementation-Plan前三项，本次追加第4项及同一功能的第5项分块验收测试；
未创建M6发布标签。

## 已完成

1. 四个接口：FrameReader、FrameWriter、AccessUnitReader、AccessUnitWriter。
   明确输出所有权、同步消费、帧边界EOF和封装元数据边界；AU接口目前仅契约。
2. `NewYUVReader(src, width, height, format)`：8-bit420/422/444，奇数色度向上取整，
   只读紧密Y/U/V。每帧独立分配且平面capacity不越过自身；PTS=帧序号、Duration=1，
   单位为一帧，不推断FPS。帧边界EOF，截断同时匹配ErrInvalidData/io.ErrUnexpectedEOF；
   错误后不继续消费。尺寸先限界到8192×8192再乘法，空流不分配整帧。
3. `NewYUVWriter(dst)`：跳过stride填充，末行只需活动字节；写前校验全部平面。
   结构错误可更正后重试，短写/传输错误后停止追加；不写尺寸、格式、时间戳元数据。
4. `NewAnnexBReader(src, maxNALSize)` / `ReadNAL()`：复用已有NAL Scanner，
   支持3/4字节起始码与任意分块，单NAL默认8MiB（含header，不含起始码/尾零），
   另有固定64KiB读缓冲。NAL Payload为独立EBSP，后续读取不覆盖。
   严格拒绝起始码前非零垃圾、无完整起始码的非空流、末尾空起始码；
   不完整封装同时匹配ErrInvalidData/io.ErrUnexpectedEOF，错误与EOF均粘性。
   观察前导/终端状态只使用固定大小状态，不复制输入或重复实现NAL切分内核。

Reader/Writer均非并发安全，不关闭调用方I/O，也不自行启动goroutine。
这些是原始I/O能力，不表示Encoder新增422/444或高位深支持。
AnnexBReader只切分NAL并解析header，不组装AU、不生成帧/时间戳，也不验证
RBSP或残差完整性；这些检查仍由后续语法/解码层负责，不能据此关闭M6尾帧门禁。

## 验证与明确边界

- `stream`已知3×3布局分别17/21/27字节，为独立字节解析解，非仅自往返。
- 单字节输入、每个截断位置、重复EOF、独立帧/Release、I/O错误保留、资源/时间戳限界通过。
- 三种格式非对齐stride、最小末行、已知输出字节、两帧往返及输入释放后输出不变通过。
- 末平面非法时无任何输出，结构错误后可重试；短写和底层传输错误粘性测试通过。
- Annex-B固定字节向量在1/2/3/7/4096/整文件分块下完全一致，含前导零、混合起始码、转义零和末尾header-only EOS。
- 无需EOF即可在下一个起始码处交付前NAL；后续chunk正确续接。EOF同次携带数据、包装EOF、坏尾部前完整NAL保留均通过。
- 前导垃圾、空NAL、非法header、残缺尾部、超大NAL提前拒绝、粘性错误及独立Payload所有权通过。
- 最新`CGO_ENABLED=1 go test -race -count=1 ./stream`通过，1.039秒，仅记录该包race。
- 最新CGO=0完整常规门禁通过：gofmt无输出、vet/build、非缓存全包test（codec29.128秒）、depscheck30包、manifest27条。
- 本轮未重跑全库race、六目标交叉编译或一小时稳定性；上述stream包race不扩写为全库race证据。
