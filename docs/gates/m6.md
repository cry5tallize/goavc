# M6接手记录：原始I/O与有界AU Reader，整体WIP

日期：2026-11-14；分支`feat/m6-streaming`；Go1.27.4 windows/amd64。
已完成Implementation-Plan前七项（含第5项分块验收测试）；
未创建M6发布标签。

## 已完成

1. 四个接口：FrameReader、FrameWriter、AccessUnitReader、AccessUnitWriter。
   明确输出所有权、同步消费、帧边界EOF和封装元数据边界；AU Writer目前仅契约。
2. `NewYUVReader(src, width, height, format)`：8-bit420/422/444，奇数色度向上取整，
   只读紧密Y/U/V。每帧独立分配且平面capacity不越过自身；PTS=帧序号、Duration=1，
   单位为一帧，不推断FPS。帧边界EOF，截断同时匹配ErrInvalidData/io.ErrUnexpectedEOF；
   错误后不继续消费。尺寸先限界到8192×8192再乘法，空流不分配整帧。
3. `NewYUVWriter(dst)`：跳过stride填充，末行只需活动字节；写前校验全部平面。
   结构错误可更正后重试，短写/传输错误后停止追加；不写尺寸、格式、时间戳元数据。
4. `NewAnnexBReader(src, maxNALSize)` / `ReadNAL()`：复用已有NAL Scanner，
   支持3/4字节起始码与任意分块，单NAL默认8MiB（含header，不含起始码/尾零），
   另有固定64KiB读缓冲。NAL Payload为独立EBSP，后续读取不覆盖。
   严格拒绝起始码前非零垃圾、无完整起始码的非空流、末尾空起始码；
   不完整封装同时匹配ErrInvalidData/io.ErrUnexpectedEOF，错误与EOF均粘性。
   观察前导/终端状态只使用固定大小状态，不复制输入或重复实现NAL切分内核。
5. `NewAVCCReader(src, lengthSize, maxNALSize)`：1..4字节大端长度前缀，默认
   8MiB单NAL，复用NAL层分配前校验。`NewAVCCReaderFromConfig(src, avcC, maxNALSize)`
   从提供的avcC记录取得宽度；不猜测字节流格式，也不拆MP4 box。
   配置中的SPS/PPS/SPS扩展复制后先交付，再读样本；构造/配置交付不消费样本输入。
   参数集使用新增`nal.ParseAVCDecoderConfigWithLimit`在复制前校验同一NAL预算，
   原无额外限制解析入口保持兼容；记录总长度按标准计数与16-bit长度的最大值先限界。
   零长度、坏header、残缺前缀/载荷为ErrInvalidData，超限为ErrResourceLimit；
   未实现avcC版本为ErrUnsupported，其他I/O错误保留errors.Is语义，错误与EOF粘性。
6. `NewAccessUnitReader(src NALReader, AccessUnitConfig)`：复用nal.Assembler和完整slice header解析，
   按序缓存SPS/PPS；默认BoundaryPicture比较frame_num/PPS/IDR/参考标志/POC0或1的各delta，
   可选BoundaryFirstMB额外按非冗余first_mb=0拆分。AUD/SPS/PPS/SEI归后AU，filler与EOS归前AU；
   最近VCL摘要跨filler保留，EOS之后的新图像即使标识重复也开始新AU。
   独立四字节起始码Annex-B Packet，KeyFrame仅IDR，PTS/DTS/Duration全0，不推断B帧时钟。
   默认单AU32MiB（含起始码/header）和4096 NAL；输入预算减法检查先于RBSP复制，
   保留的NAL另行复制，允许源复用缓冲。最多预读下一AU一个NAL，源本身仍须限制单NAL。
   正常EOF交付末AU；无VCL前缀尾部为ErrInvalidData；错误粘性，不输出半AU。
   仅渐进8-bit420 I/P/B，字段/FMO/冗余/分区等显式Unsupported；不验证slice data完整性。

Reader/Writer均非并发安全，不关闭调用方I/O，也不自行启动goroutine。
这些是原始I/O能力，不表示Encoder新增422/444或高位深支持。
AnnexBReader/AVCCReader只切分NAL并解析header，不组装AU、不生成帧/时间戳，也不验证
RBSP或残差完整性；这些检查仍由后续语法/解码层负责，不能据此关闭M6尾帧门禁。

## 验证与明确边界

- `stream`已知3×3布局分别17/21/27字节，为独立字节解析解，非仅自往返。
- 单字节输入、每个截断位置、重复EOF、独立帧/Release、I/O错误保留、资源/时间戳限界通过。
- 三种格式非对齐stride、最小末行、已知输出字节、两帧往返及输入释放后输出不变通过。
- 末平面非法时无任何输出，结构错误后可重试；短写和底层传输错误粘性测试通过。
- Annex-B固定字节向量在1/2/3/7/4096/整文件分块下完全一致，含前导零、混合起始码、转义零和末尾header-only EOS。
- 无需EOF即可在下一个起始码处交付前NAL；后续chunk正确续接。EOF同次携带数据、包装EOF、坏尾部前完整NAL保留均通过。
- 前导垃圾、空NAL、非法header、残缺尾部、超大NAL提前拒绝、粘性错误及独立Payload所有权通过。
- AVCC手写1..4前缀向量×1/2/3/7/4096/整文件分块一致；逐字节截断、零长度/坏header、超大长度在读载荷前拒绝、所有权与EOF测试通过。
- avcC取宽度、参数集快照及先交付、不提前消费样本、每处截断、版本/类型错误与分配前预算测试通过。
- AU独立比特/字节向量覆盖无AUD多slice、IDR/帧号/POC、AUD/SEI/filler/EOS、模式选择、复用源缓冲、AVCC输入、CABAC终端转义、资源与粘性错误。
- 5份登记语料（Baseline/Main/High多slice、CABAC IPB、POC1）×1/2/3/7/4096/整文件分块，AU内容逐字节一致；每AU slice数与登记值一致。
- 本轮ffprobe独立重读上述5份语料，帧数分别6/4/12/3/6，与AU数量一致；未以header测试替代残差Oracle。
- 最新`CGO_ENABLED=1 go test -race -count=1 ./nal ./stream`通过，nal1.044秒、stream1.185秒，仅记录这两个包race。
- 最新CGO=0完整常规门禁通过：gofmt无输出、vet/build、非缓存全包test（codec29.680秒）、depscheck30包、manifest27条。
- 本轮未重跑全库race、六目标交叉编译或一小时稳定性；上述stream包race不扩写为全库race证据。
